# github-administration audit B: topics 05–07

Scope: decks/github-administration/notes/05-policies-rulesets.json, 06-audit-logs-monitoring-compliance.json and 07-security-features-incident-response.json. That is 294 cards (103 + 88 + 103), including 62 scenario cards (21 + 17 + 24). None are pool cards. I checked every card against its `evidence` first. Where a back or explanation went beyond the evidence, I grepped research/sources/github-administration/. The pages I searched were: About rulesets, Creating rulesets for repositories in your organization, Enforcing code governance with rulesets, Available rules for rulesets, Streaming the audit log, Displaying IP addresses in the audit log, Restricting network traffic with an IP allow list, Using the audit log API, Push protection, Secret security with GitHub, Code scanning with CodeQL, Repository security advisories, Revoking authorizations or deleting credentials, Reviewing credentials, GitHub security features and Adding a security policy. All of them are GitHub Docs, tier B (CC BY 4.0; CONTENT-POLICY.md §3, tier B). I used no tier-C Microsoft Learn text and fetched nothing from the web.

**Pass 1 (true and sourced).** I found no wrong or unsupported claims. Every claim beyond its evidence was confirmed elsewhere in the cached page. These were: allowed exceptions for Restrict file paths; the “configured with code scanning” condition; the public-preview note on multiple stream endpoints; `api.request` events without repository context; `per_page=100` in the API examples; “Creates an alert” on a push protection bypass; Secret categories in the risk assessment; additional queries only with advanced setup or an external CI system; admin permission to request a CVE; and the “Authentication security” page for the credential inventory.

All of them match.

**Scenario letters.** All 21 topic-5 cards explain exactly the three wrong options and never the key. Two of them read awkwardly. In new-enterprise-assumption the letters are out of order (“C and B”). In hotfix-pattern the stated reason does not fit option C. None of the 41 scenario cards in topics 6 and 7 carry letters in choicesExplained. I mapped each sentence to its option by hand, confirmed that none explains the key, and patched all 41 with letters in choice order.

**Spelling.** Topic 5 spells “organisation” in prose. Topics 6 and 7 used “organization” (and “authorization”) in 39 cards, so I patched them. I kept GitHub’s spelling in names: the action “Revoke SSO authorizations”, and anything inside backticks. Those patches change the choices and the back together, so the keys still echo their choices.

**Terms from github-foundations.** No card in these topics lists a topic-0 term in `introduces`. Topic 5 uses “branch protection rule”, “outside collaborator” and “fork” without re-teaching them. Topic 7 uses “dependency graph” and “security manager” without re-teaching them. Only security-policy-file re-teaches a foundations card (SECURITY.md). I logged it without a patch.
