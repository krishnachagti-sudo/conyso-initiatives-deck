# az-104 audit C: topics 09–11

Scope: decks/az-104/notes/09-containers.json to 11-virtual-networks.json, 245 cards (56 + 116 + 73). None are pool cards. I checked every card against its `evidence` first. Where a claim went beyond the evidence, I grepped the cached text in research/sources/az-104/. For topic 09 that meant the ACR intro and SKUs, the ACI overview, container groups and portal quickstart, and the Container Apps overview, environment, plans, workload profiles, containers and scale-app pages. For topic 10: App Service hosting plans, plan management, scale up, automatic scaling, SSL certificate and bindings, custom domain, backup, networking features, access restrictions, virtual network integration, staging slots and the .NET quickstart. For topic 11: the virtual network FAQ, concepts and best practices, peering overview, UDR overview, public and private IP addresses, routing diagnosis, next hop, IP flow verify and connection troubleshoot.

Every card in these topics cites a MicrosoftDocs GitHub page (CONTENT-POLICY.md §3, tier B). No card cites learn.microsoft.com, so I fetched nothing from the web. I found no card that relies on a training-unit claim the docs contradict. Where the two could differ, I followed the docs.

## Patches

There are 9 findings, and each one has a patch in az-104-fixes-c.jsonl (9 lines). `node build/apply-fixes.mjs az-104 research/deck-briefs/az-104-fixes-c.jsonl --dry` reports every patch clean. In my first draft of the dom-root-record patch I named "RFC 1912". The checker rejects "RFC" as an abbreviation the deck does not teach, so the patch now says "an internet standard for domain names".

Checked and left unchanged:
- az104.virtual-networks.subnet-resize: its "Only when…" paraphrases the FAQ's conditional answer ("if no VMs or services are deployed in it").
- az104.app-service.managed-cert-primer: "App Service creates" matches the custom-domain tutorial ("wait a few minutes for App Service to create the managed certificate").

No finding needs more research.
