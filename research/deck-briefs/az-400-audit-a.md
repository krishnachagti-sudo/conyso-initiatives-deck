# az-400 audit A: topics 01–05

Scope: decks/az-400/notes/01-flow-of-work.json to 05-repository-management.json. That is 389 cards: 280 basic, 9 cloze and 100 scenario (58 + 60 + 55 + 111 + 105 by topic). None are pool cards. I checked every card against its `evidence` first. Where a claim went beyond the evidence, I grepped research/sources/az-400/. The pages I checked that way were the Boards–GitHub pages (index, connect-to-github, link-to-from-github, install-github-app), end-to-end traceability, about-notifications, add-link, the dashboards overview and widget catalogue, the CFD guidance, what-is-analytics, the wiki pages, service hooks, the Teams apps, branch policies, branch permissions, the branching guidance, merging with squash, the GitHub protected branches, rulesets and merge queue pages, manage large files, optimise repository performance, git tags, undo, restore deleted branch, remove binaries, multi-repo checkout, templates, the GitHub large files and sensitive-data pages, and git-fat.

Three sources are tier C and hold no saved text: the Learn page "How Microsoft develops with DevOps" and git-scm.com's `scalar` and `git-reflog` pages. I read each of them once with a generic User-Agent and sent no personal details. They support the trunk-based, Scalar, enlistment and reflog cards, but not one explanation on the release-flow card (patched below). What these sources may be used for is set out in CONTENT-POLICY.md §3 (tiers B and C).

I read every command and YAML fragment against its source and found them all correct: `az devops wiki create --type codewiki …`, `.github/release.yml` and its `changelog.exclude.authors`/`categories[*].labels` keys, `merge_group`, `resources: repositories:`, `refs/tags/<name>`, `git-filter-repo --sensitive-data-removal --invert-paths --path`, `*.png filter=fat -crlf`, `git fat push/pull`, `scalar clone --full-clone`, the `git reset` flags, `HEAD@{2}` and `@azure repos subscribe`.

In every one of the 100 scenario cards, the letters in `choicesExplained` match the choices they explain. None explains the key, and every distractor is covered. A few list their letters out of order ("D and C"), but each letter still points at the right option.

DORA metrics: none of these topics has a card on deployment frequency, change failure rate or time to restore. The brief says so too (az-400.md, "Not verified": "No Azure DevOps or GitHub page read defines time to recovery"). This is a coverage gap for objective 2 and needs research. There is no card to patch.

Re-taught terms: 17 cards teach what github-foundations already covers. Three of them repeat a github-foundations card word for word, and their concepts also sit on other az-400 cards, so I have marked those three for deletion. The other 14 carry az-400 concepts that no other card holds. Whether to drop those concepts is an editorial choice for the concept list, so I have logged them below as minor with no patch. None of the cards re-teaches an az-104 term.
