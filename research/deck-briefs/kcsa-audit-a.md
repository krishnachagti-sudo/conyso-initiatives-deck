# KCSA deck audit (A): topics 01 to 09

Auditor A, 25 September 2026, following research/deck-briefs/AUDIT.md. Scope:
decks/kcsa/notes/01 to 09, **593 cards**. Checked against the sources saved in
scratch (sources/kcsa, including the kubernetes/website clone at commit
1e1be1d, which serves v1.37; the release-1.28 4C's page; the CNCF whitepaper v2;
SSCBPv2; the lexicon; NIST SP 800-190; the NIST CSRC glossary; and the tool doc
repos). KCNA terms count as known. Mechanical checker findings
(research/deck-briefs/kcsa-fix.txt) are not repeated here.

**Counts (139 lines, 138 cards):** wrong 17 · unsupported 38 · ambiguous 9 ·
unclear 8 · minor 67.

**Source tiers.** 573 cards cite tier-B sources: Kubernetes docs and the CNCF
TAG Security papers (CC BY 4.0), NIST (public domain), and OPA, Gatekeeper and
Kyverno (Apache 2.0). **20 cards cite sources the deck itself labels tier C**:
11 Sigstore docs, 9 SLSA spec, all in 04 Supply chain. They fail the
"tier A or B only" requirement until the policy owner clears the licences or
the cards are re-sourced. Two Gatekeeper cards are mislabelled CC BY 4.0
instead of Apache 2.0. No tier-D source was found.

**Version-dependent behaviour.** The following were checked against the saved
v1.37 docs and are correct:
- PodSecurityPolicy: deprecated in v1.21, removed in v1.25.
- Legacy service account tokens: no longer auto-created from v1.24; the
  LegacyServiceAccountTokenNoAutoGeneration gate was removed in v1.27.
- TokenRequest tokens: 1-hour default lifetime.
- `allowPrivilegeEscalation`: defaults to true.
- RuntimeDefault seccomp: can be made the default since v1.27.
- ValidatingAdmissionPolicy: GA in v1.30.
- Webhook TokenReview version: defaults to v1beta1.
- Webhook authentication cache: 2 minutes.
- Authorization config reload: every 60 seconds.
- PSA: modes, version labels and exemptions.
- NodeRestriction: not a default plugin.
- The 4C's page: removed after v1.28.

Errors found:
- The AppArmor annotation claim is out of date (the field replaced it).
- "AlwaysPullImages is a default plugin" is wrong.
- The mutating-webhook reinvocation claim is wrong.
- Legacy token cards leave out the one-year cleanup of unused auto-generated
  tokens.
- A handful of cards that state version-dependent defaults are not marked
  volatile (listed at the end).

**Three most serious problems**
1. k8ssec.cloud-native-model.layer-classification teaches that restricting
   network access to the API server is a Cluster-layer control. The 4C's page
   puts it in the Cloud layer, and the deck's own infrastructure-security card
   says so too. cluster-layer-fact also misdescribes the Cluster table.
2. k8ssec.authentication.app-contractor-needs-revocable says disabling an OIDC
   account "takes effect immediately". The docs say an id_token "can't be
   revoked" and stays valid until it expires. contrast-oidc-vs-webhook also says
   webhooks are called "on every request", though decisions are cached for 2
   minutes by default.
3. The 20 tier-C cards (Sigstore, SLSA) in Supply chain, plus
   k8ssec.workload-isolation.apparmor, which says AppArmor is applied "through
   an annotation" when v1.37 uses `securityContext.appArmorProfile`.

Format: `id | pass | severity | problem | source text or plainer wording`.
