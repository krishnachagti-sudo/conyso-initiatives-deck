## Traps

- [T1] The training lists Delta Lake with Parquet and Avro as an optimised format. Parquet is columnar; Avro is row-based, with a JSON header. Delta Lake adds a transaction log on top of Parquet.
- [T1] Vector data (embeddings) now appears in the unstructured-data unit. Older material doesn't mention it.
- [T2] A document database is a kind of key-value database whose value is a JSON document. "NoSQL" means nonrelational, even though some NoSQL stores support a SQL variant.
- [T3] ACID "consistency" (a transaction moves the database from one valid state to another) is not Cosmos DB's consistency levels (T9).
- [T3] ETL transforms before loading. ELT loads first and transforms afterwards, and the training calls ELT "common in modern lakehouses". The training now calls an OLAP model a "semantic model", and historically a "cube".
- [T4] The training adds an **AI engineer** role and Microsoft Foundry. The outline still names only database administrators, data engineers and data analysts.
- [T5] DDL (CREATE, ALTER, DROP, RENAME) changes objects; DML (SELECT, INSERT, UPDATE, DELETE) changes rows; DCL (GRANT, DENY, REVOKE) changes permissions. DROP removes a table and all its rows. DELETE or UPDATE without WHERE affects every row. SQL has no "are you sure?" prompt.
- [T5] SQL doesn't enforce a primary key on every table ("Each table should have a primary key, although SQL doesn't enforce this rule").
- [T5] Indexes speed up reads but use storage and slow inserts, updates and deletes. On a small table the optimiser may ignore the index.
- [T6] **Hyperscale size conflict.** The training unit says Hyperscale supports databases "up to 100 TB". The sql-docs Hyperscale page says "up to 128 TB of database or 100 TB elastic pool size". Teach 128 TB for a database and cite sql-docs.
- [T6] SQL Server on Azure VMs is IaaS. SQL Managed Instance and SQL Database are PaaS.
  - **Compatibility:** Managed Instance is "near 100%" compatible with SQL Server Enterprise Edition. SQL Database "isn't fully compatible".
  - **Availability:** the training table gives 99.99%, 99.99% and 99.995%. The 99.995% figure was found only in the tier-C training unit.
- [T7] Flexible Server is the recommended deployment option for new MySQL workloads. Backups: the training says point-in-time restore for "up to 35 days (seven days by default)"; the MySQL Learn page says "a retention period of 1 to 35 days".
- [T8] **Data Lake Storage naming.** The training says "Azure Data Lake Storage Gen2", and the streaming unit says "Azure Data Lake Store Gen 2". The azure-docs page calls it "Azure Data Lake Storage", which "builds on the capabilities pioneered by Azure Data Lake Storage Gen1". Enabling the hierarchical namespace on an existing account is one-way.
- [T8] Blob tiers:
  - **Hot** is the default.
  - **Minimum retention:** cool 30 days, cold 90 days (on general-purpose v2 accounts) and archive 180 days.
  - **Archive** is offline: a blob must be rehydrated before it can be read, which "can take up to 15 hours".
  - Blob folders are virtual unless the hierarchical namespace is enabled.
- [T8] Page blobs, not block blobs, back VM disks. Append blobs allow appends only.
- [T8] NFS Azure file shares aren't supported on Windows or macOS, and they need an SSD-tier account and a virtual network.
- [T8] The training recommends Azure Cosmos DB for Table over Azure Table Storage for new key-value workloads. Table Storage is "still available and supported".
- [T9] The SQL API was renamed the **NoSQL API** in 2023. The API is chosen when the account is created.
- [T9] **Cosmos DB numbers.**
  - Five consistency levels; Session is "the most widely used".
  - A logical partition holds up to 20 GB.
  - One RU is roughly the cost of reading a 1-KB item.
  - Shared database throughput covers up to 25 containers.
- [T9] A serverless account runs in a single Azure region, so global distribution needs provisioned throughput.
- [T9] Cosmos DB is a poor fit for complex multi-table joins (use Azure SQL Database) and for large-scale historical analytics (use Fabric). The Cosmos DB unit still says "or Azure Synapse Analytics".
- [T10] **Synapse is not in the outline.** The analytics objective names Azure Databricks and Microsoft Fabric. The study guide's documentation list and the Cosmos DB unit still mention Azure Synapse Analytics. Older DP-900 material centres on Synapse; it is taught here as an extra concept only.
- [T10] **Lakehouse versus warehouse in Fabric.** The lakehouse uses Spark and holds structured and unstructured data, with no multi-table transactions. The warehouse uses T-SQL, holds structured data and supports multi-table transactions. The lakehouse's SQL analytics endpoint is read-only.
- [T10] Azure Data Factory is the standalone service. Fabric Data Factory is recommended inside Fabric, and both use pipelines with linked services. A shortcut references data without copying it; mirroring replicates a database into OneLake continuously.
- [T10] Medallion layers: bronze holds raw data as it arrived, silver holds cleansed and conformed data, and gold holds aggregated, business-ready data. OneLake is one lake per tenant, and every Fabric workload shares it.
- [T11] Batch latency is "typically a few hours"; stream latency is "seconds or milliseconds". The lambda architecture combines a batch layer and a stream layer; the kappa architecture drops the batch layer.
- [T11] Azure IoT Hub is like Event Hubs but optimised for IoT devices. Event Hubs delivers in order within a partition, "at-least-once". Stream Analytics is PaaS; Fabric Real-Time Intelligence is part of Fabric.
- [T12] Power BI Desktop is a Windows application for building models and reports. The service is where users publish, share and consume, with limited editing in the browser. A star schema has dimensions linked directly to facts; a snowflake schema adds tables such as a Category table under Product.
- [T12] Copilot in Power BI needs Fabric F2 or higher, or Power BI Premium P1 or higher. Smart narrative works without a Copilot licence.
- [All] Microsoft Learn is **not** available during Fundamentals exams.
