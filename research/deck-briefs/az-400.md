## Traps

- [T1] `AB#` in a commit, PR or issue links GitHub to a work item; words such as "fixes" before it also move the work item's state.
- [T2] Lead time runs from work item creation to Completed; cycle time from first In Progress to Completed.
- [T2] "Time to recovery" appears in the objective, but no Azure DevOps or GitHub Docs page read defines it (see Not verified).
- [T4] Branch protection rules block force pushes and branch deletion by default, but by default their restrictions "don't apply to people with admin permissions".
- [T4] Rulesets have no priority: rules targeting the same branch are aggregated, and "the most restrictive version of the rule applies". Branch protection rules layer with them.
- [T4] Azure Repos squash merge keeps "just the file changes"; a regular merge keeps the file changes and the commit history.
- [T4] Porting a release-branch fix: "Use cherry-picking instead of merging". Azure DevOps' own team fixes the mainline first and ports to release; both approaches are documented.
- [T5] "Azure Repos doesn't support Secure Shell (SSH)" for Git LFS.
- [T5] If sensitive data is a secret, revoke or rotate it first; rewriting history comes second and has side effects for every clone.
- [T5] `scalar clone` fetches only commit and tree objects and turns on sparse-checkout, unless `--full-clone` is given.
- [T6] A published package version is "permanently reserved": it cannot be overwritten, or deleted and republished.
- [T6] Every feed has three views by default: `@local`, `@prerelease`, `@release`.
- [T6] Project-scoped feeds inherit project visibility; organisation-scoped feeds are "Always private by default".
- [T8] Free tier for private projects: one Microsoft-hosted job, up to 60 minutes a run, 1,800 minutes a month, and it must be enabled. Paid jobs run up to 360 minutes.
- [T8] Microsoft-hosted agents give "a freshly imaged agent for each job".
- [T8] By default, pipeline secrets are not given to pull request builds from forks of GitHub repositories.
- [T9] Azure Repos Git has no YAML `pr:` trigger in effect: "Azure Repos Git uses branch policies to implement PR triggers."
- [T9] Cron schedules are in UTC. A scheduled run is skipped when nothing changed, unless `always: true` (default false).
- [T9] Setting `condition` replaces the default condition, so the item "might run even if the build is canceled".
- [T10] Template limits: 100 YAML files, 100 nesting levels, 20 MB of memory while parsing.
- [T10] Task groups belong to Classic pipelines; YAML reuses steps through templates.
- [T10] Environments serve YAML pipelines; Classic pipelines use deployment groups instead.
- [T10] In GitHub Actions, environment protection rules must pass before the job goes to a runner, and only then can it read environment secrets.
- [T11] YAML deployment jobs support runOnce, rolling and canary. Rolling works on a fixed set of virtual machines.
- [T11] Blue-green keeps the blue pool live and routes a subset of traffic to green; a canary goes to successively larger user groups. Both are progressive, and the WAF page calls canary "a common example of progressive exposure".
- [T12] Azure Automation DSC for Linux "has retired on 30 September 2023" (include file, read raw); Machine Configuration is the Azure Policy feature for audit and configuration.
- [T12] Machine Configuration has three enforcement modes: Audit, Apply and Monitor, Apply and Autocorrect.
- [T14] Workload identity service connections using the Azure DevOps issuer (`vstoken.dev.azure.com`) "are deprecated and will retire on July 1, 2027"; new ones use the Microsoft Entra issuer.
- [T14] Stakeholder access is free and unlimited, but limited on private projects. Public projects "convert to private in 2027". A GitHub Enterprise licence gives Basic access regardless of the assigned level.
- [T14] GitHub repository roles, least to most: Read, Triage, Write, Maintain, Admin.
- [T14] `GITHUB_TOKEN` expires when the job finishes or at its maximum lifetime.
- [T15] Secret variables are not decrypted into environment variables automatically; each task must map them.
- [T15] GitHub OIDC with Azure needs the `id-token: write` permission and a federated credential in Entra ID.
- [T16] GitHub Advanced Security is now sold as two products, Secret Protection and Code Security; GHAzDO customers can migrate from bundled to standalone billing, which counts active committers.
- [T16] Defender for Cloud DevOps security docs are not openly licensed: facts only, own words (tier C).
- [T18] KQL operators are joined by `|`: each takes a table and returns a table.
