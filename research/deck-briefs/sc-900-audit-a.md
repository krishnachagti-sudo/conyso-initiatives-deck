# sc-900 audit A: topics 01–04

**Scope.** I checked 416 cards in decks/sc-900/notes/01-security-compliance-concepts.json to 04-entra-authentication.json (136 + 80 + 85 + 115). None of them are pool cards. I checked each card against its `evidence` first, then checked claims beyond the evidence against the source.

**Sources.** Tier B means the MicrosoftDocs GitHub text in research/sources/sc-900/ (CONTENT-POLICY.md §3, tier B). The Learn training units are tier C (CONTENT-POLICY.md §3, tier C) and have no cached text (their manifest path is null). I fetched the 18 cited units for topics 1–4 once each, to check facts, with a generic User-Agent and no personal details. I did not save them to the repository.

**Main finding.** 32 of the 57 multiple-choice cards have `choicesExplained` lettered for an earlier choice order. Each one calls the correct option wrong and leaves one wrong option unexplained. I found them all by script (the key letter appears in choicesExplained, or a wrong letter is missing) and re-lettered each one by hand against its choices.

**Checked and found sound.** The Zero Trust principles and seven pillars, the shared responsibility split (including the SaaS/PaaS/IaaS cards and the image alt text against the matrix), the CIA, encryption and GRC cards, the identity concepts (tokens, protocols, AD DS, federation), identity types and device states, Cloud Sync versus Connect Sync, the primary and secondary method table (the course lists Authenticator push as primary: Yes), SSPR (security questions retiring March 2027, 0–730 days), security defaults, and the Password Protection scoring (the B3acon7x example scores 3). Product names follow current naming. There is no Azure AD wording, and the only edition names are Free and P1/P2.

**Not patched.** `adds-kerberos` and `external-examples` hint at a second example without naming it (NTLM; RSA SecurID). Naming them brings in abbreviations the glossary lacks, which fails the checker, so I left both cards unchanged.
