## Traps

- [T1] The activity log keeps events for 90 days; longer retention needs a diagnostic setting (export to a workspace, storage or Event Hubs).
- [T1] Resource logs are collected only through a diagnostic setting; each resource can have up to five.
- [T1] Log tables have three plans (Analytics, Basic, Auxiliary); total retention can be set up to 12 years. Do not confuse analytics retention with long-term retention.
- [T1] The Azure Monitor Agent is the supported agent; the Log Analytics agent is "legacy". Older material still teaches the legacy agent.
- [T2] Microsoft Entra ID is the current name; the SQL docs still gloss it as "formerly Azure Active Directory". Outdated material says Azure AD, Azure AD Connect and Azure AD B2C.
- [T2] Password hash sync, pass-through authentication and federation are three different methods; PTA needs on-premises agents (the docs recommend three).
- [T2] A system-assigned managed identity is deleted with its resource; a user-assigned one has its own lifecycle.
- [T3] Azure roles (resources) and Microsoft Entra roles (directory) are separate; a Global Administrator gets Azure access only by elevating to User Access Administrator.
- [T3] Key Vault soft delete: once enabled it "can't be disabled"; retention 7–90 days, default 90. Purge protection is optional and "not enabled by default".
- [T3] Microsoft recommends the user delegation SAS, secured with Entra credentials rather than the account key.
- [T4] Tags are not inherited by resources from a resource group or subscription; use Azure Policy to apply them.
- [T4] Azure Policy controls resource state; Azure RBAC controls who can act. Start with audit or auditIfNotExists before deny, modify or deployIfNotExists.
- [T4] Azure Blueprints (Preview) retires on 31 January 2027, with a phased retirement from 31 July 2026; the docs point to deployment stacks and template specs.
- [T4] Management group trees support up to six levels of depth and 10,000 management groups per directory.
- [T5] vCore versus DTU purchasing models; vCore tiers are General Purpose, Business Critical and Hyperscale. Hyperscale storage goes up to 128 TB.
- [T5] Read scale-out is on by default in Premium and Business Critical and not available in General Purpose.
- [T6] Archive is an offline tier with retrieval latency of hours; minimum retention is 30 days (cool), 90 (cold) and 180 (archive) on general-purpose v2 accounts, or an early deletion charge applies.
- [T6] Cosmos DB has five consistency levels (Strong, Bounded staleness, Session, Consistent prefix, Eventual); Session is the most widely used. A logical partition holds up to 20 GB.
- [T6] Durability: LRS 11 nines, ZRS 12 nines, GRS and GZRS 16 nines. Read access to the secondary needs the RA- variants.
- [T8] SQL Database point-in-time restore keeps 1–35 days (default 7); long-term retention up to 10 years. Do not confuse the two.
- [T8] Cosmos DB continuous backup (7-, 30- or 35-day tiers) cannot be switched back to periodic.
- [T8] Recovery Services vault and Backup vault protect different workloads; Azure Backup restores data, Site Recovery replicates for failover.
- [T9] Up to four readable geo-secondaries with active geo-replication; failover groups add read-write and read-only listeners. A forced failover can lose data.
- [T9] An availability set has up to three fault domains; a resource that uses two or more availability zones is resilient to a zone failure.
- [T10] The Functions Consumption plan is "legacy" and retired on Linux; the Flex Consumption plan is the current serverless plan.
- [T11] Azure Cache for Redis has a retirement timeline for all SKUs; Microsoft recommends moving to Azure Managed Redis. Older material teaches Azure Cache for Redis tiers.
- [T11] Storage queue messages up to 64 KB; Service Bus 256 KB, or 100 MB on Premium. FIFO in Service Bus needs sessions.
- [T11] Service Bus, Event Grid and Event Hubs are easily confused: the messaging guide calls a command "a high-value message that has strict delivery requirements"; Event Hubs is the streaming platform with Kafka compatibility.
- [T12] The Cloud Adoption Framework now lists seven phases: Strategy, Plan, Ready, Adopt, Govern, Secure and Manage. Migration strategies are eight: Retire, Rehost, Replatform, Refactor, Rearchitect, Replace, Rebuild, Retain.
- [T13] Front Door is global HTTP(S); Traffic Manager is global DNS-based for non-HTTP(S); Application Gateway is regional; Load Balancer is layer 4, regional or global.
- [T13] Application Gateway V1 was retired on 28 April 2026; teach v2 only.
- [T13] Route selection: longest prefix match first; with the same prefix, user-defined route, then BGP, then system route.
- [T13] NSG rules run in priority order, 100–4096, lowest number first.
- [T13] ExpressRoute does not go over the public internet; each circuit has two connections. Peering is not a transit path unless gateway transit is configured.
- [T13] A private endpoint is a network interface with a private IP from your VNet; a service endpoint instead switches the source of service traffic from public to private VNet addresses.

## Languages

French, Spanish, Portuguese (Brazil), Chinese (Traditional) and Italian (exam

the source repositories was checked; the MicrosoftDocs repositories fetched are
