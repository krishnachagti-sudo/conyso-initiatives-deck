# az-104 audit A: topics 01–04

Scope: decks/az-104/notes/01-entra-users-groups.json to 04-storage-access.json. That is 396 cards (99 + 81 + 126 + 90). None are pool cards. I checked every card against its `evidence` first. Claims that go beyond the evidence were checked by grepping research/sources/az-104/: SSPR how it works, what is B2B, B2B quickstart, role assignments list portal, RBAC and directory admin roles, custom roles, assignment structure, storage network security (and its overview), SAS overview, stored access policy, account keys, and the two Azure Files identity articles.

All the cited text is tier B, from the MicrosoftDocs GitHub repositories (CONTENT-POLICY.md §3, tier B). No card cites a training unit, so there was no disagreement between units and docs to settle.

The classic-administrator retirement note is an include on the cited rbac-and-directory-admin-roles page. It is not in the cache. I read it once from raw.githubusercontent.com (azure-docs `articles/role-based-access-control/includes/classic-administrators-retirement-note.md`, tier B), using a generic User-Agent and no personal details. The two topic 2 patches quote it.

Topic 3 has 126 cards against a budget of 112. I was not asked to cut it, so I have not.

Topic 4 has 90 cards against a budget of 60. I found 13 cards that repeat another card and marked them for deletion. That leaves 77 cards. Of the concepts those cards covered, only which-rule-app's had no other card, so its conceptIDs move to resource-instance-rules-primer. Getting from 77 to 60 means cutting 17 cards that do not repeat anything, which is an editorial choice. The weakest candidates are firewall-restrictions, delimiter, no-extra-charge, sap-create-shared-key, expressroute-nat, source-ad-ds, kep-rotate-first, two-keys and sas-three-controls.
