# github-administration audit A: topics 01–04

Scope: decks/github-administration/notes/01-enterprise-structure.json to 04-roles-teams-access.json. That is 279 cards (65 + 80 + 65 + 69). None are pool cards. I checked every card against its `evidence` first. Where a claim went beyond the evidence, I grepped research/sources/github-administration/. The pages I searched were: About GitHub Enterprise Server, Enterprise accounts, About GitHub for enterprises, GHEC with data residency, Deciding whether to configure SAML, Authorizing a personal access token for use with SSO, About authentication with SSO, Enforcing policies for security settings, Requiring 2FA in your organization, About mandatory 2FA, Configuring SCIM provisioning for EMU, About Enterprise Managed Users, Abilities and restrictions of managed user accounts, About custom repository roles, Repository roles for an organization, Viewing people in your enterprise, Exporting membership information, Creating enterprise teams and About IAM with SAML SSO. All of them are GitHub Docs, tier B (CC BY 4.0; CONTENT-POLICY.md §3, tier B). I used no tier-C Microsoft Learn text and fetched nothing from the web.

Volatile facts checked against the cached pages as of 26 September 2026: the trial lengths (GHEC 30 days, GHES 45 days); the data residency regions (EU with Norway and Switzerland, Australia, US, Japan); the example API address (`https://api.octocorp.ghe.com` in the source, `acme` on the card); OIDC and CAP for Entra ID only, with one OIDC integration per tenant; the mandatory 2FA periods (45 days plus a 7-day grace period); the team sync limits (5,000 per team, 10,000 per organization, 1,500 teams); the enterprise team limits (2,500 teams, 5,000 users, 1,000 organizations); and the custom role limits (20 each, or five on GHES before 3.19). All of them match.

I checked scenario letters with a script and then by eye. All 61 scenario cards (13 + 21 + 12 + 15) explain exactly the three wrong options and never the key. In base-write-consultant, "A and C:" covers both letters. Topic 4 writes keys and explanations as "D:" rather than "D)", and its backs paraphrase the choice ("not counted in" / "not in"). The checker accepts both, so I did not patch them. Topic 4 also spells "organisation" and "licence", while topics 1–3 and github-foundations keep GitHub's "organization". This is a style decision for the deck owner, so it is not patched card by card here.

Terms from github-foundations: no card lists a topic-0 term in `introduces`. Five cards still re-teach a foundations card in substance. organizations-in-enterprise repeats "one or more organizations", idp-controls-details repeats emu-controls word for word, inherit-triage and inherit-maintain repeat what-is-triage and what-is-maintain, and security-team-access is almost the foundations security-managers scenario. The first four are patched. The fifth is logged only, because the security manager role is not one of the 29 reused terms.

Duplicates within the deck: the guest collaborator fact and contrast appear in both T3 and T4. I kept the T3 cards, added the T4 concept to them and deleted the T4 copies. The T4 scenario guest-contractor-internal asks a different question, so it stays. why-leave-self-hosting duplicates ghes-or-residency-for-location, which has the same concept.
