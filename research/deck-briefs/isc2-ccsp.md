## Outline

Source: outline PDF `#page=4`–`#page=14`, same order as the web page. Six domains,
38 objectives. Items are summarised; the PDF has the full "e.g." lists.

**Domain 1. Cloud Concepts, Architecture and Design: 17%**
- 1.1 Understand cloud computing concepts: definitions [T1]; roles and responsibilities (customer, CSP, partner, broker, regulator) [T1]; essential characteristics (six, incl. multi-tenancy) [T1]; building-block technologies [T1]
- 1.2 Describe cloud reference architecture: activities, capability types, service categories, deployment models (incl. multi-cloud) [T2]; shared considerations (interoperability … outsourcing) [T2]; related technologies (AI, blockchain, IoT, containers, quantum, edge, confidential computing) [T2]
- 1.3 Understand security concepts relevant to cloud computing: cryptography and key management, identity and access, sanitisation (overwriting, cryptographic erase), network security (NSGs, inspection, geofencing), virtualisation security (hypervisor, container, ephemeral, serverless, isolation), common threats, hygiene (patching, baselining, immutable, hardening) [T3]
- 1.4 Understand design principles of secure cloud computing: secure data lifecycle, secure design patterns, DevOps security, responsibilities by category, functional requirements (portability, lock-in) [T4]; cloud BC/DR planning, BIA (CBA, ROI) [T10]
- 1.5 Evaluate Cloud Service Providers: verification against criteria [T4]; product certifications (Common Criteria, FIPS 140-2) [T3]
- 1.6 Comprehend AI/ML: threat detection, data source validation, SOAR, ethics, regulation [T5]

**Domain 2. Cloud Data Security: 20%**
- 2.1 Describe cloud data concepts: life-cycle phases, dispersion, flows [T6]
- 2.2 Design and implement cloud data storage architectures: storage types, threats [T6]
- 2.3 Design and apply data security technologies and strategies: encryption and keys, hashing, obfuscation, tokenisation, DLP, keys/secrets/certificates [T6]
- 2.4 Implement data discovery: structured, unstructured, semi-structured, location [T7]
- 2.5 Plan and implement data classification: policies, mapping, labelling [T7]
- 2.6 Design and implement IRM: objectives, tools (certificate issue and revocation) [T7]
- 2.7 Plan and implement retention, deletion and archiving policies; legal hold [T8]
- 2.8 Auditability, traceability and accountability of data events: event sources and attributes, logging, chain of custody and non-repudiation [T8]
- 2.9 Comprehend data protection of AI and ML data: data set and model privacy and security [T5]

**Domain 3. Cloud Platform and Infrastructure Security: 17%**
- 3.1 Comprehend cloud infrastructure components (web page: "and platform components") [T9]
- 3.2 Design a secure data centre: logical, physical, environmental, resilience [T9]
- 3.3 Analyse risks associated with cloud infrastructure and platforms: assessment, vulnerabilities/threats/attacks, treatment [T9]
- 3.4 Plan and implement security controls: physical, system/storage/communication, IAA, audit mechanisms [T9]
- 3.5 Plan BC and DR: strategy, requirements (RTO, RPO), plan creation and testing [T10]

**Domain 4. Cloud Application Security: 16%**
- 4.1 Advocate training and awareness for application security: basics, pitfalls, common vulnerabilities (OWASP Top 10, ASVS, API Top 10, LLM Top 10, SANS Top 25) [T11]
- 4.2 Describe the secure SDLC process: business requirements, phases, waterfall vs agile [T11]
- 4.3 Apply the secure SDLC: cloud-specific risks, threat modelling (STRIDE, DREAD, ATASM, PASTA), secure coding (ASVS, SAFECode), configuration management [T11]
- 4.4 Apply cloud software assurance and validation: functional/non-functional, testing methods (SCA, IAST, SAST, DAST), QA, abuse cases [T11]
- 4.5 Use verified secure software: APIs, supply chain, third-party, validated open source [T12]
- 4.6 Specifics of cloud application architecture: WAF, DAM, XML firewall, API gateway, load balancer; cryptography; sandboxing; microservices and orchestration [T12]
- 4.7 Design appropriate IAM solutions: federation, IdP, SSO, MFA, CASB, secrets [T13]

**Domain 5. Cloud Security Operations: 17%**
- 5.1 Build and implement physical and logical infrastructure: HSM, TPM, secure by default, management plane, virtual hardware (hypervisor type 1 and 2), guest tools [T14]
- 5.2 Operate and maintain infrastructure: remote access, network configuration (VLAN, TLS, DHCP, DNSSEC, VPN), network controls, OS hardening, patching, clustering and HA, monitoring, backup [T14]
- 5.3 Implement operational controls and standards (ITIL-style processes: change, continuity, information security, improvement, incident, problem, release, deployment, configuration, service level, availability, capacity) [T15]
- 5.4 Support digital forensics: collection, evidence management, preservation [T16]
- 5.5 Manage communication with relevant parties [T15]
- 5.6 Manage security operations: SOC, monitoring, SIEM, IR, vulnerability assessment, penetration testing [T15]

**Domain 6. Legal, Risk and Compliance: 13%**
- 6.1 Legal requirements and unique risks in cloud: conflicting laws, legal risk, frameworks, eDiscovery (ISO/IEC 27050), forensics (ISO/IEC 27037/41/42/43) [T16]
- 6.2 Understand privacy requirements (web: "issues"): contractual vs regulated data, country laws (FERPA, PIPEDA, GDPR, HIPAA, DPDP Act), jurisdiction, ISO/IEC 27018 and GAPP, PIA [T16]
- 6.3 Audit processes and adaptations for cloud: internal/external, assurance challenges, SOC/SSAE/ISAE reports, scope restrictions, gap analysis, planning, ISMS, policies, stakeholders, regulated industries (NERC CIP, HIPAA, HITECH, PCI), distributed IT [T17]
- 6.4 Implications of cloud for enterprise risk management: provider risk programmes, data roles, transparency (breach notification, SOX, GDPR), risk treatment, frameworks, metrics, risk environment [T17]
- 6.5 Outsourcing and cloud contract design: SLA/MSA/SOW, vendor management (lock-in, viability, escrow), contract clauses, supply chain (ISO/IEC 27036) [T17]

## Traps

- The **outline changed on 1 August 2026**, so material written before then follows an earlier outline. The old outline was not fetched, so what is new (possibly the AI/ML objectives 1.6 and 2.9) is not verified. Do not state old weights. [T5]
- **Format.** CCSP is now CAT in every language: 100 to 150 items in 3 hours, with no going back to review an item. Older material describing a fixed-form linear exam is out of date. [T1]
- **Five or six characteristics.** NIST SP 800-145 has five, with multi-tenancy inside resource pooling. ISO/IEC 17788 (ITU-T Y.3500), which the outline follows, lists six, adding multi-tenancy and "rapid elasticity and scalability". [T1]
- **Roles.** ISO/IEC 17789 treats broker and auditor as sub-roles of cloud service partner. NIST SP 500-292 lists five actors: consumer, provider, carrier, auditor and broker. The outline uses the ISO words ("cloud service customer", "partner"). [T1]
- **Capability type vs service category.** Application, platform and infrastructure are *capability types*. SaaS, PaaS, IaaS, CaaS, CompaaS, DSaaS and NaaS are *categories*. [T2]
- **FIPS 140-2 vs 140-3.** The outline still names FIPS 140-2, but FIPS 140-3 says: "This standard supersedes FIPS 140-2". [T3]
- **Clear, purge and destroy.** These are three different methods, and cryptographic erase is a *purge* technique (SP 800-88 Rev. 2). Rev. 2 (September 2025) "Supersedes NIST SP 800-88r1". [T3]
- **RTO, RPO and MTD.** SP 800-34: "Because the RTO must ensure that the MTD is not exceeded, the RTO must normally be shor[ter]". RPO measures data loss (a point in time), not downtime. [T10]
- **Risk responses.** The outline lists five (avoid, mitigate, transfer, share, accept). SP 800-39 treats "Risk Sharing or Transfer" as one response. [T9]
- **OWASP Top 10 has a 2025 edition.** A03:2025 "Software Supply Chain Failures" and A10:2025 "Mishandling of Exceptional Conditions" are new names. Material built on the 2021 list is out of date. [T11]
- **"SANS Top-25"** in the outline is the CWE Top 25, which MITRE publishes (the 2025 list was fetched). [T11]
- **Superseded NIST guides.** SP 800-61 Rev. 3 (April 2025) supersedes Rev. 2 and is now "A CSF 2.0 Community Profile". Material built on Rev. 2 is out of date. SP 800-63-4 supersedes 800-63-3. [T15] [T13]
- **Outline spelling errors.** The outline writes "HIPPA" (twice in the PDF) and "Comittee Of Sponsoring Organizations". The act is HIPAA; never copy the misspellings. [T16]
- **Hypervisor types.** SP 800-125 calls them "bare metal" and "hosted". The outline says "type 1 and 2". [T14]
- **Experience substitutes.** An active CISSP replaces the whole experience requirement. CCSK or a degree replaces only one year, and "Only one year of experience can be waived". [T1]
- **Contractual vs regulated data**, and controller vs processor. These are classic confusions, and the GDPR text is not verified here (see below). [T16] [T17]

## Languages

The exam is offered in English, Chinese (Simplified), German and Japanese. Chinese is
offered only in set appointment windows. The ISC2 outline page links Chinese
(Simplified), German and Japanese PDFs of the outline, which are all rights reserved. The ITU-T
Y.3500 page also links other-language PDFs (PDF-A, PDF-C, PDF-S …); their languages
were not checked. NIST publications are English only. No openly licensed translation of
the main sources was found.
